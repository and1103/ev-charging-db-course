# C 模块验收记录

目标环境为 MySQL 8.4、InnoDB、PyMySQL 和 Flask。本记录只描述 C 模块的数据库行为，不把其他业务线的历史通过结果混入本模块结论。

| 场景 | 实际断言 | 第三版验证 |
| --- | --- | --- |
| 工单顺序 | 未接单不能直接到场；未到场不能修复；关闭前必须有修复结果 | 通过 |
| 维修前样本 | 修复前三条旧样本不能恢复告警 | 通过 |
| 来源枪状态 | 来源枪仍为 fault 时不能恢复 | 通过 |
| 正常恢复 | 三条新近正常采样、心跳新鲜且来源枪可用后写入恢复时间 | 通过 |
| 同源去重 | 同桩、同枪、同故障码重复上报复用同一活动告警 | 通过 |
| 枪级区分 | 同一桩的不同枪产生不同活动告警 | 通过 |
| 整桩兼容 | `connector_id=NULL` 的整桩告警与枪级告警可以并存 | 通过 |
| 跨桩枪拒绝 | 来源枪不属于目标桩时，函数调用和直接写入均被拒绝 | 通过 |
| 活动视图 | `v_live_alarm` 暴露活动告警、所属场站、来源枪和 active 状态 | 通过 |
| 集成烟雾测试 | A/B/C/D/E 关键业务链在合成事务中执行并回滚 | 通过 |

第三版验证记录中，`C_regression_monitor.sql`、`regression_alarm_scope.sql` 和 `C_smoke.sql` 的结果均为 `passed=true`。原始日志保存在本地过程目录，未将运行日志或数据库连接信息提交到仓库。

复现入口：

```sql
SOURCE 实现/C/设备监控与故障工单/smoke.sql;
SOURCE 实现/C/设备监控与故障工单/测试/C_regression_monitor.sql;
SOURCE 实现/C/设备监控与故障工单/测试/regression_alarm_scope.sql;
```

回归脚本会回滚业务夹具，但创建和删除测试存储过程属于 DDL，自动递增编号可能产生空号。当前小样本通过不等于已经证明大数据量性能或生产环境高可用。
