# 可选图件维护工具

运行平台不需要Node或本目录工具。这里用于SQL结构变化后维护图与字典；34张正式PNG已随第二版保留，本次整合没有重绘图片。

## 文件用途

| 文件 | 用途 | 是否改图 |
|---|---|---|
| 生成图件.py --check | 只读解析第二版02目录DDL，与模型清单核对实体/字段/联系 | 否，不改清单或PNG |
| 核对图模.py | 对比模型与已有结构快照，更新一致性JSON及索引核对段 | 不改PNG，也不连数据库 |
| 模型清单.json | 44表、79关系、源文件位置及20份SQL的原始审计哈希 | 静态资料 |
| render_manifest.json | 34份内嵌布局文本、源哈希及第二版PNG目标路径 | 静态资料 |
| render.mjs --check | 验证所有PNG目标在第二版内且布局哈希正确 | 否，无需npm依赖 |
| qa.mjs --check | 验证清单中的34个PNG存在且不越出工程 | 否，无需npm依赖 |
| render.mjs | 显式重绘34张正式PNG，SVG仅在内存转换 | 是，维护者主动执行 |
| qa.mjs | 用已有PNG生成QA拼版到过程文件/本次整合/图件QA | 只生成新的QA PNG |
| 目视检查记录.md、渲染结果.json | 原图的历史目视/渲染记录，路径已迁移 | 不等于本次又重绘或目视验收 |

## 安全的离线核对

在第二版根目录运行（Python环境安装后）：

```powershell
.\01_平台工程\.venv\Scripts\python.exe .\03_需求与设计\图件维护工具\生成图件.py --check
.\01_平台工程\.venv\Scripts\python.exe .\03_需求与设计\图件维护工具\核对图模.py
node .\03_需求与设计\图件维护工具\render.mjs --check
node .\03_需求与设计\图件维护工具\qa.mjs --check
```

结构快照位于[数据库结构快照.json](../模型与数据字典/数据库结构快照.json)，来自2026-11-14的已有导出，不冒称本次重新连接数据库。结构变化时先更新实库元数据与CSV，再改模型/字典，不直接涂改PNG上的表名。

模型中的20个SQL哈希保留原审计轨迹：包括业务DDL、回归、Workbench展示及两轮历史备份，不表示有20份独立建表脚本。所有路径已转向第二版内部，只有02目录的业务DDL用于当前概念模型解析。

## 需要重绘时才安装维护依赖

进入本目录运行`npm ci`，依赖及版本由package-lock.json锁定，使用本地标准node_modules解析。已去掉具体Codex安装版本路径；不要求其他组员安装Codex工具运行时。

然后先不带--check运行生成图件.py，准备新模型、索引及布局清单；再运行`node render.mjs`重绘，最后人工检查PNG并更新目视记录。需要QA拼图时运行`node qa.mjs`。本次整合仅执行--check及图模核对，没有安装渲染依赖、没有执行以上重绘步骤。

旧7张QA拼图见历史目视检查。正式图索引见[图件索引](../图件索引.md)，字段语义见[完整字典](../模型与数据字典/数据库设计与数据字典.md)。
