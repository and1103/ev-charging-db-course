# 数据库设计第二版

新能源汽车充电桩运营服务平台，整合日期：2026-11-16。

本目录是后续阅读、运行与维护的统一入口：以已有Flask网页工程为运行底座，合入初版数据库的全部业务SQL、部署样例、测试、Workbench展示、设计图件、数据字典与备份恢复工具。同一份运行代码和DDL只维护一份；早期Word、候选方案和旧验收放入历史记录，不作为当前操作说明。

## 1. 先运行起来

默认使用 MySQL 8.4 的 `127.0.0.1:3307 / charge_course_20261114`。从 GitHub 获取后，先安装依赖，再按平台工程说明配置本机连接或建专用库。

| 根目录入口 | 用途 | 使用方式 |
|---|---|---|
| [启动平台.cmd](启动平台.cmd) | 检查环境和数据库，启动本版后台并打开网页 | 直接双击 |
| [停止平台.cmd](停止平台.cmd) | 关闭本版网页后台并核对5000端口 | 直接双击，窗口显示结果 |
| [安装环境.cmd](安装环境.cmd) | 在新电脑/重建环境时安装锁定的Python依赖 | 已有环境无需重复安装 |
| [运行验证.cmd](运行验证.cmd) | 默认执行快速检查；可指定测试组 | 双击或在终端传入组名 |

网页地址：`http://127.0.0.1:5000/ui/`。启动器会识别第二版实例，5000若被旧工程占用会给出提示；它不会把旧服务当作本版运行成功。关闭浏览器标签不会关闭后台，结束使用请运行“停止平台.cmd”。

演示账户为管理员 `admin`、车主 `driver1` 等。演示密码和加密配置在各自电脑上设置，操作见[平台工程说明](01_平台工程/README.md)。

## 3. 推荐阅读顺序

1. 查看[原任务要求和模板](06_任务资料与小组分工/README.md)，明确课程提交内容和五人主责。
2. 阅读[需求与设计](03_需求与设计/README.md)：参与者、业务闭环与用例/鲁棒图，再看Chen E-R、全局UML和关系模式。
3. 对照[数据字典](03_需求与设计/模型与数据字典/数据库设计与数据字典.md)理解字段、单位、主外键、函数依赖、约束和索引；再打开对应的[五线SQL](02_数据库脚本/README.md)。
4. 从[平台工程](01_平台工程/README.md)了解页面如何经HTTP接口、事务与持久层落入MySQL，按角色实际操作。
5. 用[统一测试和Workbench](04_测试与验收/README.md)按订单号、流水号、工单号、结算号核验；最后了解[备份恢复](05_备份与恢复/README.md)。

完整对应关系另见03板块的功能与任务清单。设计流程保持“需求分析→概念设计→逻辑设计→物理设计→建库建表→持久层与应用→测试保护与交付”。

## 4. 业务线与协作边界

| 主责 | 本线做什么 | 与其他线的关键交接 |
|---|---|---|
| A 场站设施与排队 | 运营商/站/桩/枪、投运验收、状态历史、取号叫号和留枪转单 | B提供开单/计费约束，D提供本人车辆和支付身份 |
| B 订单与计费 | SOC报价、计量、分时核价、授权冻结、付款/退款和异常复核 | D维护钱包/卡/券，E接收真实收退款及历史金额 |
| C 监控与工单 | 桩级采样、桩/枪告警、派单到维修关闭、正常观察恢复 | A维护资产状态，B处理活动订单/断连的资金状态 |
| D 用户与会员 | 登录、车辆绑定、会员钱包、活动券、企业车队与额度 | B操作资金闭环，E处理消费开票申请与企业金额核对 |
| E 结算与对账 | 账期快照、完整外账、差异双方意见、整单双签、消费与结算蓝红票 | B交付交易事实，D提供消费申请及车队账单 |

五条主线可对应五位成员；A包含排队子模块，六套局部图不代表六个人。共用同一个后端与数据库，不能为分工复制五套收费公式或同一张表。

## 5. 怎样验证

在根目录终端中可运行：

```powershell
.\运行验证.cmd quick
.\运行验证.cmd api
.\运行验证.cmd workbench
.\运行验证.cmd all --start-http
```

具体分组、管理员权限和副作用以04板块说明为准。默认快速检查不会重建数据库；API/并发组使用真实合成数据，会刷新种子设备并可能保留取消订单。带新库DDL的空库验证和备份恢复属于单独管理员操作，不进入默认all。

历史PASS保留原日期。第二版是否通过，以 `过程文件/本次整合` 的本版记录为准。HTTP与代码DOM检查不能代替真实浏览器画面、鼠标点击和排版验收；先前浏览器工具的本地访问审批未获准，本次不会绕过该限制。

## 6. 当前范围与后续工作

现有结构基线为44张业务表、19视图、25存储过程、15函数和54触发器；部署控制表另计。正式图和字典逐项对照，不笼统宣称全部物理表严格3NF，受控冗余在字典中单独说明。

网页当前保留既有精简版功能：费率版本只读、进度/叫号按刷新读取、调度为单次执行，设备/支付/税务是明确模拟输入。完整历史筛选、费率写入页面、自动轮询/周期任务、复杂查询大样本优化前后对照、PITR等仍需继续实现或演练；不能把“目录合并完成”写成这些功能已经验证完成。

## 7. 给其他成员时怎么用

- 只阅读：直接看本文件和03、06板块，不需要运行数据库。
- 当前电脑同一Windows用户：已准备环境，直接使用根目录启停入口。
- 其他电脑：运行“安装环境.cmd”重建虚拟环境，并按[平台说明](01_平台工程/README.md)选择连接已有库或管理员新建库；Windows DPAPI配置不能跨账号直接解密。
- 分享源码/报告时，排除 `01_平台工程/.local`、`.venv`、`node_modules` 和运行日志；依赖由锁文件重建。原Web根已有的密码文件已收进本机私有区，没有复制到公共说明。

原“数据库课设初版”和“充电运营服务平台Web版”目录保留为来源备份。后续修改以本第二版为准，避免三处同时改动。
