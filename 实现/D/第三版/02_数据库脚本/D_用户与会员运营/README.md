# D 用户与会员运营

本目录负责“谁在使用平台、车辆属于谁、钱包和会员权益如何使用，以及企业用车如何记账”。

| 文件 | 作用 |
|---|---|
| [02_schema.sql](02_schema.sql) | 用户、车辆、有效绑定、车队、用车卡、活动与优惠券，以及相关约束 |
| [05_members.sql](05_members.sql) | 钱包流水、优惠核销、消费开票申请、订单反馈、会员/车队查询等与订单关联的对象 |
| [10_wallet.sql](10_wallet.sql) | 模拟充值函数：请求号重放、金额及引用一致性、余额与流水原子写入 |
| [queries.sql](queries.sql) | 场站活动核销、未用有效券、车队月消费的三对查询 |

主要表为`account`、`vehicle`、`vehicle_binding`、`fleet`、`fleet_card`、`campaign`、`coupon`、`wallet_entry`、`redemption`、`consumer_invoice_request`、`driver_feedback`。

## 正确使用顺序

1. A基础设施就绪后执行`02_schema.sql`。B订单和A排队基础就绪后执行`05_members.sql`。最后按全局顺序执行`10_wallet.sql`，不能把三个文件连续提前执行。
2. 新注册车主由管理员核验；添加车辆会建立当前有效绑定。解绑、转移及车队开卡需遵守车辆归属和活动订单约束。
3. 钱包余额、冻结和可用金额分开显示。模拟充值不连接银行；重复请求号只能入账一次，不能只更新余额而不写流水。
4. 活动领取与核销要满足会员等级、场站、时刻、库存与消费门槛。用车卡月额度和单笔充电授权是两类约束。
5. 消费开票申请在本线登记，实际票据由E线财务流程签发/红冲；不要混淆“提出申请”和“已开票”。

密码随机盐哈希、会话和网页RBAC由平台Python代码实现；手机号/车牌采用密文与脱敏显示。本目录的`account.role`是业务角色，和MySQL数据库登录用户/数据库角色不同。

完整依赖与权限见[数据库总说明](../README.md)。已有用户、资金流水和券核销不应通过重跑样例脚本重置。
