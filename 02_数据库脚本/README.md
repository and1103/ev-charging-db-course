# 02 数据库脚本：结构、约束、业务对象与样例

本板块是第二版的**唯一业务SQL来源**。`01_平台工程/deploy.py`通过`project_paths.py`定位这里的文件，网页运行时访问MySQL，不会每次启动都重新建表。

## 先判断自己要做什么

| 目的 | 应使用的内容 | 是否写数据库 |
|---|---|---|
| 在本机使用已有网页和课程库 | 回到第二版根目录启动网页；本目录只作为设计依据阅读 | 网页操作按具体业务写入 |
| 阅读表结构、约束、视图与存储程序 | 下面五个业务目录的结构SQL | 阅读文件不写库 |
| 执行课程多表查询 | 每个业务目录的`queries.sql` | SELECT查询只读 |
| 在独立空库复现完整数据库 | `部署工具`，按下列全局依赖顺序部署，再加载三组样例 | 会建对象并写入合成数据 |
| 核对已有库或验证业务 | `04_测试与验收`中的工具和Workbench脚本 | 依具体工具说明，部分会使用临时夹具 |
| 从备份恢复 | `05_备份与恢复` | 只恢复到明确指定的新隔离库 |

当前本机应用连接`127.0.0.1:3307 / charge_course_20261114`。文件整合不会复制、清空或重建这个库。**已有业务库不要再次手动执行整套CREATE TABLE或样例插入语句。**

完整迁移后，按[样例说明](初始化与样例/README.md)依次加载基础样例、扩展示例、车队示例。部署器使用`charge_migration`表记录版本；只有已记录的版本才会跳过。已有表与缺失版本记录并存时，应先核对结构和历史，不删除版本记录强行重跑。

## 权限与执行边界

- 创建对象需要目标库的管理权限，包括建表、约束、索引、视图、存储程序、触发器等；`deploy_local.py`还会临时调整并恢复`log_bin_trust_function_creators`，执行账号必须具备相应管理权限。
- 数据库管理员在自己的本地会话提供`CHARGE_ADMIN_DSN`。普通网页使用的应用账号只有业务读写和EXECUTE等权限，不能用它代替DDL管理员。
- 新库复现必须先明确新目标库；现有主课设库与历史验证库均不得清空覆盖。MySQL的DDL可能隐式提交，不应把“失败后ROLLBACK”当作完整建库回退方案。
- `.local/runtime.dpapi`保存本机受保护运行配置；它不是通用管理员连接，也不能直接跨Windows用户使用。账号口令、PII密钥和实际连接串不写在本目录说明中。

新读者先读[部署工具说明](部署工具/README.md)和[样例说明](初始化与样例/README.md)，再执行对应命令。已有网页正常运行时，无需重新部署数据库。
