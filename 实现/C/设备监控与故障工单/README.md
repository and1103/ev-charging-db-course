# C 设备监控与故障工单

本模块负责设备遥测、告警范围、维修工单和恢复复核。它回答三个问题：设备是否正常、异常来自哪把枪、维修完成后能否安全恢复。

## 文件入口

| 文件 | 作用 |
| --- | --- |
| `07_monitor.sql` | 遥测分区、告警规则、来源枪校验、告警去重、工单流转、离线扫描、升级和恢复复核 |
| `queries.sql` | 场站分级响应时间、逾期未响应和重复维修的三组等价查询 |
| `模块设计.md` | 用例、鲁棒关系、实体联系和跨业务线接口 |
| `字段.csv`、`约束.csv`、`索引.csv` | 从第三版数据库导出的结构核对资料 |
| `smoke.sql` | 覆盖跨业务链的集成烟雾测试 |
| `测试/C_regression_monitor.sql` | 工单顺序、恢复前后样本和来源枪状态的专项回归 |
| `测试/regression_alarm_scope.sql` | 同源去重、不同枪区分、跨桩枪拒绝和活动告警视图回归 |
| `check_queries.py`、`concurrency.py` | 查询等价性与同一枪并发开单检查 |
| `scheduler.py` | 手动执行一次离线扫描、告警升级和排队调度 |

## 关键约束

- 遥测主键为 `(charger_id, sampled_at)`，同一桩同一时刻不能写入两条记录。
- `connector_id` 为空表示整桩告警或来源枪未细分，不表示所有枪都发生故障。
- 同一桩、同一来源枪、同一故障码只保留一条活动告警；恢复后允许产生新的历史事件。
- 工单必须按接单、到场、修复、关闭推进，关闭时必须有维修结果。
- 恢复需要工单全部关闭、维修后有连续正常采样、心跳新鲜，且来源枪不处于故障或离线状态。

## 执行顺序

`07_monitor.sql` 依赖 `charger`、`connector`、`account` 和订单相关对象，应先完成前置业务线建表，再按项目部署顺序执行本脚本。

在仓库根目录打开 MySQL 客户端并选择项目数据库后执行：

```sql
SOURCE 实现/C/设备监控与故障工单/smoke.sql;
SOURCE 实现/C/设备监控与故障工单/测试/C_regression_monitor.sql;
SOURCE 实现/C/设备监控与故障工单/测试/regression_alarm_scope.sql;
```

回归脚本使用事务夹具并在结束时回滚，但仍需要创建和删除临时存储过程的权限。

## Python 检查

从仓库根目录运行：

```powershell
python .\实现\C\设备监控与故障工单\check_queries.py
python .\实现\C\设备监控与故障工单\concurrency.py
```

两个脚本需要已部署的课程数据库和对应的 `CHARGE_DATABASE_URL`。并发测试会创建并取消一张合成订单。

执行一次维护扫描：

```powershell
python .\实现\C\设备监控与故障工单\scheduler.py
```

该入口不是常驻定时器；需要周期执行时，应由外部计划任务调用。
