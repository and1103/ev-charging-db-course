# B 充电订单与计费

本目录负责“价格规则是什么、实际充了多少、最终应付多少，以及付款退款如何保持一致”。金额计算以服务端Decimal/MySQL数值结果为准。

| 文件 | 作用 |
|---|---|
| [03_schema.sql](03_schema.sql) | 费率版本、每日分时段、电表采样、订单、费用分段、人工复核；结束充电核价和计量边界规则 |
| [06_payment.sql](06_payment.sql) | 支付与退款、订单余额视图、幂等请求、资金和额度校验、追加授权及复核处理 |
| [queries.sql](queries.sql) | 近30天分时电量/电费/服务费、部分付款、核价对照的三对查询 |

主要表为`tariff`、`tariff_band`、`charge_order`、`meter_sample`、`fee_detail`、`order_review`、`payment`、`refund`。

## 正确使用顺序

1. 完整建库时，先有A设施和D用户车辆基础表，再执行`03_schema.sql`；A排队及D会员活动就绪后执行`06_payment.sql`。详见[全局部署顺序](../README.md)。
2. 估价只提供报价，不产生最终账单。开单后先记录订单起始时刻的累计电表读数，再记录递增采样；结束时以可信采样核价。
3. 分时边界缺读数、断连或超预算等情况可能进入复核。人工调整应保留结论，不能通过直接改金额掩盖原始计量证据。
4. 付款、充值和退款请求应保持同一请求号重试。调减客户应付与撤销原付款对欠款的影响不同，界面会区分处理。

历史订单1可用作独立核对：10kWh，原价11.40、优惠2.00、成功付款4.00+5.40、待付0。新订单费用由实际时刻、费率和计量决定，不预设与订单1相同。

本目录SQL依赖A/D对象，不能单独在空库执行。DDL需管理权限；业务过程由网页权限和数据库约束共同保护。核价、资金、边界与并发回归脚本已归入`04_测试与验收`，不是本目录的日常初始化步骤。
