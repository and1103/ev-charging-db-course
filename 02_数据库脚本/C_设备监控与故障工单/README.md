# C 设备监控与故障工单

本目录负责“设备是否正常、告警由哪把枪产生、谁维修、何时可恢复”。桩级遥测和枪级订单计量是不同数据，不能互相平均代替。

| 文件 | 作用 |
|---|---|
| [07_monitor.sql](07_monitor.sql) | 遥测、告警规则、带来源范围的告警、工单、备件、升级通知；离线扫描、超时升级及恢复校验 |
| [queries.sql](queries.sql) | 分场站/级别响应时间、逾期未响应、重复维修的三对查询 |

主要表为`telemetry`、`alarm_rule`、`alarm`、`work_order`、`work_part`、`alarm_notice`。相同来源范围的活动告警会去重；工单应按接单→到场→修复→关闭推进。

## 正确使用顺序

1. 依[全局顺序](../README.md)，A/B/D相关表和例程就绪后执行`07_monitor.sql`。
2. 管理员查看告警来源、选择符合范围的维修人员派单；维修人员只处理本人允许范围的工单。
3. 工单关闭后仍需满足修复后的新鲜正常采样及观察条件，才能恢复告警和设备状态。不能仅把设备state改成idle当作修复完成。
4. `scan_offline`、`escalate_alarms`和场站排队分配需要被调用。网页的管理员扫描按钮及`01_平台工程/维护工具/scheduler.py`是**单次调用入口**；目录中没有已安装的持续周期任务。

维护脚本说明见`01_平台工程/维护工具/README.md`。本目录结构需要DDL管理权限；派单、维修、恢复通过管理员/维修角色及数据库过程校验。监控和并发回归源码已归入`04_测试与验收`。
