# A 场站设施与排队

本目录负责“在哪充电、哪把枪可以使用、设备如何投运，以及到站后如何排队和留枪”。排队是A线子模块，不作为第六条独立业务线。

| 文件 | 作用 |
|---|---|
| [01_schema.sql](01_schema.sql) | 运营商、场站、充电桩、充电枪、资产状态历史、验收/变更申请；功率约束与投运过程 |
| [04_queue.sql](04_queue.sql) | 排队记录、叫号、留枪；设备/车辆兼容、可用状态、开单资格和排队分配 |
| [09_roles.sql](09_roles.sql) | 可选DBA脚本：为当前选定库创建/授权`charge_api`数据库角色 |
| [queries.sql](queries.sql) | 场站分枪型可用量、即将过保、近期离线的三对查询 |

主要表为`operator`、`station`、`charger`、`connector`、`asset_history`、`asset_request`、`queue_entry`、`queue_call`、`gun_hold`。场站—桩—枪归属、枪功率不超过桩功率、活动留枪唯一性及排队资格由数据库规则维护。

## 正确使用顺序

1. 完整建库时先执行本目录`01_schema.sql`；再按[全局依赖顺序](../README.md)建立D基础用户、B基础计费后，才能执行`04_queue.sql`。
2. 日常网页中先登记设备，再创建验收申请并核验投运。投运日期不等于设备在线，还需要有效心跳、营业条件及允许状态。
3. 车主可直接选择可用枪开单，或取号后在叫号截止时间前使用本人预留枪。页面显示状态是提示，最终资格由服务端再次核验。
4. 取消排队后的留枪释放及后续叫号由一次调度扫描处理；未安装周期任务时应由管理员明确运行扫描。

`09_roles.sql`不会创建网页admin/driver等业务账号，也不会自动给现有MySQL登录用户绑定角色。它应由DBA在选定目标课设库后单独执行，不能把它当作普通查询或日常启动步骤。

本目录结构SQL需要DDL管理权限；查询需要SELECT及其依赖例程权限；日常资产和排队操作通过网页角色与数据归属校验。已有库不要重跑结构或样例初始化。
