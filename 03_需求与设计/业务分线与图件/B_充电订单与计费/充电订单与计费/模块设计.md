## 需求、实体与关系

参与者为车主、车队负责人、获准的后台人员以及支付/计量模拟器。主流程为：费用估算 → 取得可用枪 → 开单预授权 → 保存读数 → 结束分段计费 → 必要的人工复核 → 优惠核销及付款 → 必要的退款 → 向E提供结算事实。

主责8表：`tariff`、`tariff_band`、`charge_order`、`meter_sample`、`fee_detail`、`order_review`、`payment`、`refund`。

费率版本1:N时段与订单；订单1:N原始读数、费用明细和付款；订单1:0..1复核记录；付款1:N退款。钱包流水、优惠券及车队资料属于D，结算及发票属于E；本线通过外键、过程和同一业务事务协作。

费率时段由 `(tariff_id,minute_from)` 标识；读数由 `(order_id,sampled_at)` 标识；付款渠道和业务流水组合保证唯一，退款引用原付款。费用快照按订单发生时保存，不能用今天的费率或场站归属覆盖历史。完整函数依赖与物理冗余说明见数据字典。

## 费用估算为什么没有单独一套SQL

`estimate_charge` 已定义在03_schema.sql，使用同一份 `tariff/tariff_band`；无需再建估算专用费率表或复制函数。旧说明中的 `tariff_slices` 不是当前实现中的函数，现以实际分时循环逻辑为准。

后端 `POST /estimate` 接收 `vehicle`、`gun`、`at`、`current_soc`、`target_soc`，可选 `card`。先校验本人车辆绑定、接口兼容、SOC范围及车队卡归属，选车队专属价或通用价，再计算：

- 所需电量 = 电池容量 × (目标SOC − 当前SOC) / 100。
- 估算功率 = 车辆最大功率与枪最大功率的较小值；估算时长 = 电量 / 功率。
- 按预计开始时刻跨峰平谷/午夜分段，计算电费和按电量或按小时的服务费，处理免费时长和起步价。

估算基于恒定功率，不包含真实充电曲线、损耗和排队等待，不能作为最终结算账单。最终费用根据原始计量读数分段核价，插值/断连及预算异常进入相应复核。估算只读，不创建排队记录、占枪或扣款。

## 主要过程、函数与视图

`estimate_charge` 估价；`meter_at` 取边界电表读数；`order_cost_until` 计算已发生费用；`inspect_charge_budget` 检查预算；`authorize_more` 追加预授权；`finish_charge` 结束核价；`approve_review` 审核异常；`post_payment` 和 `post_refund_kind/post_refund` 处理幂等收退款。

3个视图为 `v_order_balance`（实收/退款/应付/欠费）、`v_unpaid_order`（待缴订单）、`v_band_income`（历史场站分时电量和费用）。费率重叠/时段完整性、钱包或车队冻结通过实际约束与触发器保证；本人报告应选能解释的过程及触发器，并提供正反例。

## 跨线主责边界

| 跨线事项 | 主责及协作方式 |
|---|---|
| 排队、叫号、超时、留枪 | A维护[04_queue.sql](../../../../02_数据库脚本/A_场站设施与排队/04_queue.sql)及排队3表；B提供费用规则 |
| 扫码开单 `open_charge` | 物理定义在A的04脚本，以便处理留枪转单；A负责排队资格及占枪，B负责资金预算及订单状态。A维护函数入口，B评审资金相关修改 |
| 原始读数与断连 | B维护 `meter_sample`、核价与复核；C维护设备采集/异常接入，断连时按最后可信读数衔接 |
| 钱包、优惠券、车队额度 | D维护账户/卡/流水/核销；B在充电和付款事务内调用，双方复核冻结释放与退款 |
| 结算与发票 | B输出订单原费用、优惠、成功支付、退款和历史归属；E维护结算、双方确认和开票 |

共用入口在[app.py](../../../../01_平台工程/app.py)，按路由划分维护责任，并非每人运行一个独立后端。`POST /orders`、`/orders/{id}/authorize`、`/orders/{id}/cancel`、`/orders/{id}/pay`、`/payments/{id}/refund`、`/demo/order/{id}/readings`、`/demo/order/{id}/finish` 等交易路由由B主责，与相关负责人评审。

## SQL、索引及测试交付

现有queries.sql的3题是：近30天分时电量/费用、部分付款、订单原价与费用明细核对，每题2种写法。第一题展开实现明确连接费用明细、订单、场站；另一实现经 `v_band_income` 展开具有相同关系基础。说明时应展开视图，解释三表关系和聚合口径。

订单用户/时间索引、枪/结束时间索引和付款订单索引对应分页、历史充电及账单查询。每人至少选1项真实索引方案，解释执行计划与写入成本，不把索引总数当成性能提升证据。

已有测试及历史结果：

- 资金回归：预算、核价、付款退款、冻结及异常规则。
- 资金并发：同钱包/车队额度、同券、收退款幂等及旧RR快照。
- 计费边界：跨午夜、按小时服务费、免费时长及起步价。
- API权限：本人、其他车主、所属/其他车队负责人追加额度的权限。
- 查询比较：各线3题双实现及执行计划。

上述是已记录的项目测试，不代表本次整理重新执行了测试，也不代表某位同学已经独立完成。B成员后续应能手工复算固定账单、解释事务锁与回滚，并写出本人真实参与和改进记录。
