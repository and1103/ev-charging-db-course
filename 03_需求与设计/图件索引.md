# 图件索引与建模口径

原图完成日期：2026-11-14；第二版路径整合与离线核对：2026-11-16。所有图由本目录只读解析当前 SQL DDL 生成，不连接数据库、不执行 SQL。

本版覆盖 **44 个实体、79 条物理或逻辑关联**。全局图覆盖全部实体与关联；六张 UML 分区详图列出该区所有字段及直接引用的外部实体。

第二版正式图片按A—E保存在“业务分线与图件”；7张历史QA拼图在过程文件/历史记录/图件目视检查。所有正式图仅PNG，布局文本内嵌在图件维护工具/render_manifest.json中。

## 图例与一致性

- Chen E-R：矩形实体、菱形业务联系、椭圆业务属性、下划线主标识。外键通过联系表达，不再重复绘为普通属性；组合主标识合并为一个下划线属性。
- 1/N 为最大基数，N 允许 0..N；0..1 表示可选。外键必填性决定父实体端基数；唯一外键决定子实体端最多一条。跨行状态、有效期互斥等额外限制见 SQL，不由普通 1/N 代替。
- UML 分区图：PK/FK 标明标识与物理外键，‘关联’表示非物理外键的逻辑链接，‘派生’表示数据库生成列，[1]/[0..1] 表示属性必填性；不同用途的多条外键分别标注列名。总览只选主标识与关键属性，完整字段查看分区图。
- 虚线为逻辑关联：分区遥测由触发器校验桩编号；对账保留未知外部订单号时可能没有平台订单，不能伪称物理外键。
- 鲁棒图明确区分 boundary（页面/接入）、control（业务协调）、entity（领域实体），并绘出跨线控制依赖。它是需求分析模型，不是顺序图，也不是已通过接口验收的证明。
- 用例图中 include 只表示被包含的必需子行为，extend 表示条件扩展；此前/之后的业务前置条件不强行画成 include。
- 异常复核 order_review 直接关联 charge_order，未再错误挂到 fee_detail 下。旧 Word 图示说明作为背景文字保留；本索引、PNG 和模型清单是本版图结构依据。
- 告警 alarm.connector_id 为可选的真实枪来源：NULL 表示整桩或未指定枪，不把桩下全部枪伪装为来源。scope_connector 是去重用生成列，Chen 图不把它当业务属性；枪级恢复仍以桩级连续遥测为观测基础，并额外检查指定枪状态。
- 余额流水 wallet_entry.topup_ref 为可空且唯一的充值请求号；全字段 UML 保留该字段，充值幂等不再依靠负数主键。

## 重建与校核

1. 在第二版根目录用本工程Python运行 `03_需求与设计/图件维护工具/生成图件.py`（仅核对时加 --check），只读抽取建表、ALTER 新增列、主键、唯一键及外键，更新模型与内嵌布局清单。
2. 需要重绘时先在图件维护工具目录运行npm ci，再运行render.mjs；依赖版本由本地package-lock锁定，无需Codex运行时。只核对路径时运行node render.mjs --check。渲染中间格式只驻留内存，最终仅写出 PNG。
3. 核对 `图件维护工具/模型清单.json` 中的实体、字段、关系和 SQL 哈希；查看 `图件维护工具/渲染结果.json` 的尺寸与警告。
4. 目视检查 PNG；SQL 更新后必须重新生成，不能只修改图片上的表名。

新增实体自动归入其 SQL 所在业务分区；新的用例/控制协作及中文命名仍需按业务语义人工评审。全局大图用于完整性检查，报告应同时使用模块详图，避免压缩到一页导致字号过小。

## 与实库元数据核对

读取已有的 `模型与数据字典/数据库结构快照.json`，逐项比对业务表集合、字段集合、主键、必填性及物理外键列对。结果：通过；44 张业务表、320 个表字段、77 对物理外键列。75 条物理关系之外的 4 条逻辑关联均以虚线单独标明。

同时核对业务 SQL 的例程名称/类型及触发器名称：40 个例程、54 个触发器，与元数据一致。

核对依据、问题清单见 [图模数据库一致性.json](图件维护工具/图模数据库一致性.json)，可运行 `图件维护工具/核对图模.py` 复核；此脚本只读元数据导出，不连接数据库。该结构核对不替代业务、并发或权限测试。
